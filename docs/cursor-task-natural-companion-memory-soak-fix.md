# Cursor 任务：真实语音 soak 返修——偏好写入与跨领域召回

> 先读取根 `AGENTS.md`，以及 `skills/architecture-contracts/SKILL.md`、`skills/engineering-quality/SKILL.md`、`skills/collaboration-review/SKILL.md`。这是自然陪伴里程碑的真实验收返修；只完成本文范围，完成后停止等待 Codex Review。不得提交或推送，不得读取/修改/删除 `data/memory`，不得启动真实主程序、Ollama、麦克风、TTS/RVC 或设备。

## 现场证据与根因

真实语音验收中，用户表达新的冰激凌偏好后正常重启，再询问却得到旧的抹茶答案。隐私日志（不含正文）显示每轮：

```text
memory submit accepted turn_id=...
memory ingestion processed turn_id=... accepted=0
```

询问时 `memory recall done entries=1`。代码审计确认：

1. `submit accepted` 只表示队列接收；`processed accepted=0` 表示没有候选写入。
2. 本地事实语法只支持非常窄的句首断言；带明确“请记住/我想告诉你”等自然口语前缀且 STT 没有标点时会被拒绝。
3. 词法召回把“喜欢/最喜欢/我的/是什么”等询问骨架当相关度；具体对象不相干时，旧偏好仍可能仅凭“喜欢”进入上下文。
4. `SqliteMemoryStore.add()` 只做整句规范化去重。本轮禁止凭模糊语义自动删除或覆盖真实记录。

## F1：有限支持明确的“记住”口语前缀

在本地可信事实单元边界增加**小型固定白名单**，只允许此前缀后紧接现有可完整解析的第一人称原子断言。建议至少覆盖：

- `请记住我喜欢香草甜筒`
- `记住我喜欢香草甜筒`
- `你要记住我喜欢香草甜筒`
- `我想告诉你我喜欢香草甜筒`
- `我跟你说一下我喜欢香草甜筒`

可接受空白、中文/英文冒号或逗号。实现必须满足：

1. 只去除一个固定前缀后调用既有严格谓词解析；`UserFactUnit.text` 仍必须是原文完整 span，事实正文仍由本地 renderer 生成，模型只能选择 `unit_id`。
2. 不允许任意前缀搜索或在句中寻找 `我喜欢`；`别人说我喜欢…`、`如果我喜欢…`、`别以为我喜欢…`、`我不确定…`、疑问句、引用句、句尾否认继续零候选。
3. 不把单独的 `我说我喜欢…` 自动视为事实；它存在引用/转述歧义。此次现场若 STT 转成该形式，产品应在无写入时明确可观察，而不是静默声称记住。
4. 支持直接且自然的槽位句式，至少验证 `我喜欢的冰激凌是香草甜筒`、`我最喜欢的冰淇淋口味是香草` 仍能生成一个本地候选。

## F2：召回必须有对象内容相关性

修正 `src/memory/lexical_recall.py`，避免偏好记录仅凭通用关系词跨领域命中。

1. 为查询和记录派生“内容词法特征”：忽略固定记忆询问/事实框架，例如 `我/我的/用户/你知道/你记得/喜欢/最喜欢/偏好/是什么/什么/哪个/哪些/吗/呢`。使用确定性本地规则，不新增模型、embedding、分词依赖或 I/O。
2. 查询含具体内容时，候选必须与内容特征有实际交集。至少保证：
   - 仅有旧记录 `用户喜欢抹茶拿铁` 时，`我喜欢的冰激凌是什么` 和 `我喜欢什么甜筒` **不得召回**该记录；
   - `用户喜欢的冰激凌是香草甜筒` 可被上述冰激凌/甜筒问题召回；
   - 饮品问题仍可召回抹茶拿铁；英文和既有中英文召回契约不回归。
3. 查询含多个具体 CJK bigram 时，不得只因一个过宽标签词（如“口味”）召回不同对象；采用有界覆盖门槛或等价确定性规则，并为反例写测试。
4. 对真正无具体对象的广义问题（如 `我喜欢什么`），可以保持有界的偏好回忆，但必须显式识别为广义偏好查询；不得让这条 fallback 作用于含“冰激凌/饮品/甜筒”等具体对象的问题。
5. 排序仍保持相关度、importance、更新时间和稳定 id；不得读全库超过现有 `candidate_limit`。

## F3：不得静默把排队当成已记住

不改变前台异步、失败开放和零额外请求契约。补充可观察状态，但日志不能含正文：

- `memory ingestion processed` 至少继续明确 `accepted`；如能在不改变 Protocol 的前提下安全加入 `local_candidates` / `selected` / `created` / `deduped` 计数则加入。
- 若本地零候选，记录固定原因码（例如 `no_safe_fact_unit`），不记录用户文本。
- 不要求模型回答“已经记住”，也不得为了反馈增加第二次 LLM 调用或阻塞前台等待提取。

## 明确非目标

- 不做模糊语义的自动冲突覆盖；同一用户可以同时喜欢多种食物/饮品。
- 不放宽证据来源、疑问/否认/引用防污染边界。
- 不改变 memory 队列、关闭、retention、数据库权限、网络端点或人格/TTS 功能。
