# Codex Review：真实语音记忆返修

状态：**PASS**。F1–F3 已完成独立复验；未接触真实 `data/memory`，未提交或推送。

## 评审结论

首轮实现已经解决多字槽位事实的主要路径，但独立临时库探针仍复现三项阻断问题。当前版本仍可能把旧的抹茶偏好注入冰激凌问题，或让用户以为单字偏好已经被记住。

### F1（P1）：合法单字中文值仍被当成占位符

`is_placeholder_core()` 依赖 `_value_tokens()`，后者只保留长度至少为 2 的 CJK run。因此下列明确事实均为零候选：

- `我喜欢茶`
- `我喜欢猫`
- `请记住我喜欢茶`

必须修复为：

1. 明确的单字中文值可通过既有严格第一人称事实语法，例如 `茶/猫/狗`；原有疑问、未知、字段标签、条件、引用、否认边界继续失败关闭。
2. 不得通过普遍关闭 placeholder 校验实现；`我喜欢什么`、`我喜欢饮品` 等现有占位/标签反例仍须拒绝。
3. `我喜欢茶吗`、`我喜欢猫吗` 的内容特征必须分别包含具体单字，并且不得被判为广义偏好查询。

### F2（P1）：领域词查询会跨对象召回所有偏好

临时库放入 `用户喜欢抹茶拿铁`、`用户喜欢猫`、`用户喜欢香草甜筒` 后：

- `我喜欢什么饮品` 返回全部三条；
- `我喜欢什么食物` 返回全部三条；
- `我喜欢猫吗` 也被判为 generic 并返回全部三条。

当前 `_content_overlap_allows()` 在查询只有弱标签或单字时直接放行，再由通用“喜欢”获得分数；这仍是跨领域污染。

必须采用确定性的失败关闭规则：

1. 只有真正无对象的 `我喜欢什么` 才能走“全部偏好”的有界 fallback。
2. 非框架单字（如 `茶/猫/狗`）是具体内容。查询与记录必须有同一具体单字或更强内容交集；`我喜欢猫吗` 只允许猫相关记录，`我喜欢茶吗` 不允许猫或香草甜筒。
3. 只有弱领域标签（如 `饮品/食物/口味/类型`）的查询也不是 generic。优先依据规范事实中的明确 slot 匹配，例如 `用户喜欢的饮品是抹茶拿铁` 可命中 `我喜欢什么饮品`，`用户喜欢的冰激凌是香草甜筒` 可命中冰激凌问题。
4. 对没有明确 slot、且查询与 value 没有实际内容交集的旧记录，领域查询必须返回空；不要在本轮引入“拿铁必然是饮品”等脆弱词表或模型分类。`我想喝抹茶拿铁` 仍应直接命中旧的 `用户喜欢抹茶拿铁`。
5. `我喜欢什么食物` 不得召回饮品、猫或无 slot 的香草甜筒记录。若没有可证明兼容的记录，空结果优于错误记忆。
6. 保持候选上限、排序、无新 I/O/模型/embedding 依赖。

建议为查询和规范记录分别派生 `generic / concrete content / domain slot`，并使用已经存在的本地事实 parser 读取规范记录的 slot；不要用原始“喜欢”框架词做对象相关性证据。

### F3（P1）：`skip_reason` 可把任意文本写入日志

`MemoryIngestionService` 对 duck-typed `extract_detailed()` 结果执行：

```python
str(getattr(result, "skip_reason", "") or "")
```

独立探针令 `skip_reason="SECRET_USER_BODY"` 后，日志原样出现该值。这违反日志正文零泄漏边界。

必须修复为：

1. ingestion 仅允许记录仓库定义的固定原因码。当前已知合法值为 `no_safe_fact_unit`、`eligibility_skip`；如新增原因码，必须是源码常量且加入显式 allowlist。
2. 未知值、非字符串和异常对象一律映射为固定安全码（如 `unknown`）或省略；不得调用可输出任意正文的 `str()`。
3. 测试使用恶意/异常 duck-typed 结果，证明秘密字符串、对象 `__str__` 返回值和用户正文均不进入日志，同时正常固定原因码仍可观察。

## 必须新增的回归矩阵

- 单字安全反例：疑问、否认、条件、引用、未知占位和标签值继续零候选。

- 日志：固定原因码可见；任意 `skip_reason` 和带副作用 `__str__` 不可见且不被调用。
- 保留原任务的冰激凌与抹茶反例、英文召回、有界候选和稳定排序测试。
