## 先完成增量接口修正

当前 generate_stream 使用 done 真值判断。Codex 离线复现 done 为字符串 "false" 或数字 1 时，错误地产生 COMPLETED 并提交历史。

- 新增量路径中，done 若存在必须是 bool；非法类型产生 FAILED / RESPONSE_ERROR。仅 done is True 完成，False 继续；没有完成标记直到 EOF 则失败。
- 在交付本行增量前校验该行字段。
- 参数化覆盖字符串 "false" / "true"、0、1、None、列表、对象。预置成功历史，先有效增量再非法标记；验证仅一个失败终结、无成功、完整历史不变、响应关闭。
- 保持旧聚合接口不变，先跑全量离线测试。

## 随后完成一个完整里程碑

目标：提供可选择的 CLI 增量显示与分句播报路径，模型生成首个完整句子后即可进入 TTS，无需等待完整回答。保留原有非流式入口作为兼容路径。

先阅读现有 CLI、Handler、Router、Assistant、TTS、音频播放器及新增事件契约，记录简短实现决策，再实现并自测，不只交付计划。

### 边界与行为

- 系统/搜索仍先匹配且每次输入只路由、执行一次；LLM 路径仅发一次 HTTP 请求。兼容接口不可重复触发请求或系统动作。
- 业务层消费增量事件；CLI 及时显示增量，完成时不重复打印全文。失败提示与角色台词区分，不送 TTS 或角色。
- 增量分句器处理跨 chunk 的中文/英文句末标点、换行和尾部残句；成功完成时刷出尾句，失败或取消时丢弃未提交尾句。设置可说明的长度上限防止无标点文本无限缓存。
- 单个受管理播报消费者与有界队列，按顺序调用既有 TTS，避免每句新建线程。明确容量和背压行为；队列等待要能退出，消费者失败不能造成生产者永久阻塞。
- 使用轮次标识防止过期结果进入新轮次；本阶段保证应用层可停止继续生成/排队，不能在底层不支持时声称能够立刻打断已经播放的音频。
- 增量文本可能先显示或播报后生成失败，这是流式固有情况；失败后停止继续提交本轮未播放内容，不把已经播出的部分写成完整成功历史。文档明确已播音频不可撤回。
- 明确 COMPLETED 为生成完成，不是播放完成。历史仍由模型客户端在有效完成后提交一次，上层不重复提交。
- 退出时关闭生成迭代器，停止接收新播报，处理待播队列和消费者生命周期；提供有界等待与未退出的明确诊断，不谎称底层播放已停止。
- 异常路径也关闭 HTTP。消费终结事件后应显式释放迭代器，不依赖垃圾回收。
- 不引入大型框架、新依赖、长期记忆、3D 或 Quest 代码，不修改系统安全设置或注册表，不执行真实电脑控制。
- 暂不运行真实麦克风、播放、RVC 或联网语音测试；用户正在休息，真机试听留作明确未验证项。

### 离线验收

- 原有测试保持通过；修正测试须说明原因而非删弱断言。
- 可控假流证明首个文本和首个完整句子在最终完成事件前交付。
- 跨 chunk 分句、不重复、不漏尾句；错误前缀正常台词仍正常处理。
- 失败/空回复/取消不播报错误、不继续消费过期队列；保留已有历史快照。
- 背压、消费者故障、退出、生成失败使用 Event 等可控同步验证，不靠长 sleep 或真实设备。
- CLI 完整调用链的 fake 集成测试，系统/搜索优先级及单次执行验证，非流式兼容回归。
- 测试不能启动真实 HTTP、浏览器、音频设备、模型 Worker 或数据清理。
