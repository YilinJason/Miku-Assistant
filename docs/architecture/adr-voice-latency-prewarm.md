# ADR：语音首轮延迟诊断、Ollama 预热与 RVC 设备探测

## 问题与实测基线

用户在真实语音模式中感到回复很慢。按 `logs/miku.log` 中 2026-09-26 23:01 左右的一轮实际运行拆分：

- STT 成功后约 **46.2 秒**才收到 Ollama 首个增量，整轮生成约 **49.5 秒**；
- 同一进程后续热请求首增量约 **7.4 秒**、生成完成约 **8.9 秒**，说明首轮主要消耗在模型冷加载；
- 首段 edge-tts 约 **0.65 秒**，MP3→WAV 约 **2.2 秒**；
- 首次 RVC 转换约 **10.3 秒**，其中 Worker 推理约 **7.9 秒**；后续单段 Worker 推理约 1.2–2.0 秒；
- Worker 已常驻，但每段转换前仍重复运行独立 Python/torch CUDA 探测，额外约 1.8 秒。

第一阶段修改后的 23:19 真机复验表明：

- Ollama 预热约 6.1 秒，用户输入后的首增量降至 **2.877 秒**；服务端整轮指标为 `total=3.909s`、`load=2ms`、约 54.5 token/s；
- 首段 MP3→WAV 仍有 **1.303 秒**的一次性热身，后续约 9–13ms；
- 首个真实 RVC 推理仍需 **5.320 秒**，后续约 1.3 秒；
- 插话发生在 Worker 空闲间隙时，旧实现仍无条件关闭 Worker，下一轮重新加载约 5.2 秒、首次推理约 4.9 秒，使该段 RVC 总等待达到 12.1 秒。

当时只读取现有日志、`ollama ps` 和 GPU 状态，没有发起新的模型生成或音频操作。`ollama ps` 显示当前模型约占 8.3 GB 且完全在 GPU 上，因此这次不把问题误判为 CPU offload。

## 决策

1. 默认装配给 `OllamaClient` 配置 `keep_alive: "30m"`，避免空闲几分钟后再次冷加载。直接构造 `OllamaClient` 时仍默认省略该字段，保留旧调用行为。
2. 默认装配完全成功后启动一次后台空 `/api/chat` 请求，预载模型但不读取或写入会话历史。正式请求若碰到尚未结束的预热，会有界等待同一次加载，避免同时发起两次大模型加载。
3. 预热失败只记警告，正式请求继续使用原有错误契约；预热线程仅在装配成功后创建，避免装配回滚时遗留无主 HTTP 工作。
4. 记录 Ollama 终结响应中的 `total_duration`、`load_duration`、`prompt_eval_duration`、`eval_duration`、生成 token 数和 token/s。流式首增量与完成计时继续保留，日志不新增对话正文。
5. RVC Worker 缓存键使用请求中的设备配置字符串。CUDA 可用性只在创建新 Worker 时解析一次，不再按每段音频重复启动探测解释器。
6. 提供可选的 librosa 重采样预热，但默认关闭。其首次 JIT 时间在不同环境波动较大，当前真机首段额外开销约 1.3 秒，不值得默认延长且不可预测地阻塞启动。
7. Worker 模型加载完成后，对一秒低振幅测试信号执行一次完整 RVC 推理。测试音频位于 Worker 自有临时目录，不播放、不进入业务流水线，结束即删除；失败只记警告。
8. 插话时只终止正在启动、预热或推理的 Worker。Worker 已空闲时保留模型；活跃推理直接有界终止，不再先固定等待两秒。操作代际使取消前尚未发送的旧任务失效，重建与下一轮转换由同一互斥边界串行。

Ollama 的空 `messages` 加载请求、`keep_alive` 和响应性能字段依据官方 [Chat API](https://docs.ollama.com/api/chat) 与 [Generate API](https://docs.ollama.com/api/generate) 契约。

## 取舍

- `keep_alive: "30m"` 会让模型在空闲期继续占用约 8 GB 显存。需要给游戏或其他 GPU 工作让路时，可缩短该值或设为 `0`，代价是之后重新承担冷加载。
- 后台预热把冷加载移到应用初始化后的空闲时间。用户若在预热结束前立刻提问，正式请求仍需等待剩余加载时间，但不会重复加载。
- 本轮没有更换模型、缩小上下文或删减角色提示词。热态约 7 秒的首增量仍可能受 12B 模型、8K 上下文和提示词计算影响，需要用新增指标复验后再单独决策。
- RVC 首次推理会增加启动时间和一次计算峰值，以换取用户说话后的更短等待；可用 `worker_warmup_inference` 关闭。重采样预热为显式可选项。
- 测试信号不会播放，但会真实使用 RVC 模型和 GPU。它仅在用户正常启动已启用 RVC 的应用时运行；离线测试用 fake 验证协议，不自动启动真实推理。

## 验证与回退

纯离线测试覆盖预热 payload、历史不变、失败开放、后台幂等、保活字段、畸形指标、装配失败不启动预热、RVC 缓存键不触发 CUDA 探测、Worker 预热协议、临时文件回收、重采样幂等预热，以及空闲/活跃插话边界。第一阶段 Ollama 改善已经真机确认；第二阶段音频预热仍需复验。

回退可分别关闭 `ollama.warmup_on_start`、删除或缩短 `ollama.keep_alive`、关闭两个音频预热开关。插话保留空闲 Worker 的逻辑可独立回退；各项不依赖模型或音色更换。
