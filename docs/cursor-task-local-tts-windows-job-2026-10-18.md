## Chosen bounded approach: parent-owned named Windows Job, worker self-joins BEFORE heavy imports

Avoid global taskkill, process-name kills, PID guessing, admin/debug permissions, registry, direct-base-Python environment tricks, custom CreateProcess launcher or suspended-process orphan window. Python3.12 _winapi only supports handle_list, not JOB_LIST. Microsoft references:
https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects
https://devblogs.microsoft.com/oldnewthing/20230209-00/?p=107812/

Implement focused stdlib-only src/core/owned_worker_job.py (or similarly clear module), lazily loaded only for Windows local TTS. Not a new generic executable/OS capability. SafetyPolicy.spawn_local_tts_worker must still validate sealed interpreter/assets/argv and fixed env and permission FIRST. Then create one fresh unpredictable named Job (local session namespace, fixed MikuLocalTts prefix + own parent pid + uuid32hex); KILL_ON_JOB_CLOSE flag, no breakaway/silent-breakaway. Parent handle non-inheritable. CreateJobObject returning ERROR_ALREADY_EXISTS must reject (never attach to existing user's job). No system-wide objects or external PID operations. Put name in an INTERNAL env field, overwriting only after existing env allowlist creation; never inherit an ambient field or allow caller override. No new config/security permission.

The actual runtime interpreter early entry (__main__, immediately after stdlib/root sys.path setup, before src.voice/torch/numpy/etc imports) opens this exact validated name with only JOB_OBJECT_ASSIGN_PROCESS access, assigns **GetCurrentProcess() only**, and closes its local job handle immediately in finally. Require valid token + matching parent pid + parent alive; if missing/open/assign/close fails: fixed terse error + exit2 BEFORE any model/resource import/spawn. Do not create the job in child, do not fallback. Importing worker for pure unit tests must remain effect-free. Parent dying/closing job before child joins => Open fails => early exit without models; parent dying after join => last parent handle closes, job kills joined interpreter/descendants. Child must not retain/inherit a job handle across models or it defeats kill-on-parent-exit. Direct unsupported Windows runtime invocation without parent capability fails closed. Non-Windows existing path unchanged.

Parent returns Popen-compatible owned adapter retaining raw Popen and Job (stdin/stdout/stderr/pid/args delegation). terminate/kill terminate only its own Job AND its own redirector handle as needed; no arbitrary PID API. poll/wait must establish BOTH raw redirector exit AND Job ActiveProcesses==0 before returncode. A redirector exiting before child joined closes job; late child then fails early Open. Query/close failure cannot be reported complete; retain ownership/retry, never restart another model while unknown. wait(timeout) one monotonic absolute deadline, <=50ms sleeps/finite waits; no unbounded threads/daemon/reaper per cancellation. Job handle closes exactly once after fully quiescent; safe nonblocking finalizer as backup, OS parent-exit handles close anyway. Normal idle/EOF must also reap adapter, not leak native handles. Client existing poll/wait/termination path should work without changing stop/synth/start budgets; adjust minimal calls only if needed. Do not expose process/job handle to LLM/tools.

Win32 ctypes signatures/struct sizes correct x64, handles pointer-sized; explicit CloseHandle on all success/error paths. Put native backend behind a small fakeable interface. Don't silently skip containment when using custom _popen_fn; test DI must use explicit fake job backend/factory or patch helper. Any actual runtime launch in production on Windows must be contained; no isinstance-based security bypass for factories.
