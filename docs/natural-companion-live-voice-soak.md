# 自然陪伴真实语音 soak（30–60 分钟）

本清单用于开发里程碑后的人工验收。它会实际启动 Ollama、麦克风、扬声器、TTS 和已启用的 RVC；不要与诊断脚本、模型下载、游戏或其他 GPU 重负载并行运行。

## 1. 启动前

1. 确认使用主程序 Python，而不是 RVC 独立环境：

   ```powershell
   C:\Users\uitra\AppData\Local\Programs\Python\Python312\python.exe -X utf8 main.py --mode interactive
   ```

2. 保持 `config/config.yaml` 中 `assistant.companion.enabled=true`、`memory.enabled=true`、`memory.retention.enabled=true`。不要在验收时清库或运行 memory 删除计划。
3. 若允许 `cloud_stt`，麦克风音频可能发送给在线识别服务；若允许 `cloud_tts`，助手回复文本可能发送给 edge-tts。验收对话不要包含密码、令牌、身份证号或其他秘密。
4. 打开任务管理器；可选打开 `nvidia-smi -l 2`。记录启动前的 Python RSS、线程数、GPU 显存和子进程数量。

## 2. 0–10 分钟：冷启动与基础陪伴

- 先做 2–3 轮文本对话，再输入 `voice` 进入语音模式。
- 说一件普通日常小事、一件轻微烦恼和一个复杂问题。
- 观察：回应是否先贴合内容、是否避免客服腔/机械开场、是否不会每轮追问、复杂问题是否才展开步骤。
- 记录首轮和后续热轮的首 token、首音频等待；冷启动可较慢，但热轮不应持续恶化。

## 3. 10–20 分钟：长期记忆

- 自然提及一个新的、低敏感且可核验偏好，例如“我最近更喜欢焙茶”。继续聊 2–3 轮后结束程序并正常重启。
- 新会话问与该偏好直接相关的问题，再问一个无关问题。
- 通过标准：相关问题自然使用记忆；无关问题不罗列偏好；不说“根据数据库/召回”；不知道时不编造。
- 提取是异步的，刚说完立刻退出可能尚未写入；退出前留出一轮正常对话时间，并确认程序正常 shutdown。

## 4. 20–35 分钟：播报自然度与隐私投影

- 让助手回答包含普通括号词：`(API)`、`(RVC)`、`(Python 3.12)`，确认没有被吞掉。
- 让助手给出一个 Markdown 链接、一个代码块和一张 Markdown 图片示例。
- 通过标准：屏幕保留原文；语音不逐字朗读 URL、query、代码或 Markdown 标记，只使用简短固定提示；中文后文仍会继续播报；没有双句号。
- 连续给出短句、长句、中英文混合和颜文字，确认不会重复播报、漏掉整段正常文本或卡住。

## 5. 35–50 分钟：插话、失败与 Nahida 音色

- 在长回复开始播报后自然插话 5 次，间隔包含很短和较长两种情况。
- 在文本/语音模式之间切换 3 次，观察是否错误拾取助手自身声音。
- 通过标准：旧回复停止继续排队；新轮不混入旧轮；监听不会在底层音频仍未知时过早恢复。
- RVC 就绪后每轮应保持 Nahida 音色。若 RVC 明确失败，允许回退默认音色，但日志必须说明原因；不得逐句反复冷启动 Worker 或反复加载模型。

## 6. 50–60 分钟：稳定性与退出

- 保持 5 分钟空闲后再问 3 个问题，然后正常退出一次；必要时再用 `Ctrl+C` 验证中断退出。
- 通过标准：RSS、线程数、子进程数和显存进入平台期，没有随轮次持续单调增长；没有长时间 100% CPU；退出后主 Python、RVC Worker 和临时音频均按配置契约回收。
- `ollama.keep_alive` 可能让模型显存保留一段时间，这是配置行为；判断泄漏时应看它是否按 keep-alive 到期或显式卸载策略释放。

## 7. 失败时保留的信息

记下失败发生的本地时间、当轮输入类型、是否在播报/插话/切模式、日志中的异常类型和阶段耗时，以及任务管理器或 `nvidia-smi` 的资源变化。不要公开包含真实对话、记忆正文、URL 凭据或云服务令牌的完整日志。
