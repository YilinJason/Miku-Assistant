# 工程质量

## 检查范围

先读取根目录 AGENTS.md、依赖清单和已有检查配置；通过文件搜索确认测试实际分布。`test_rvc_conversion.py` 与 `diagnose_rvc.py` 是检查入口，运行前阅读代码，不能凭文件名认定它们是无副作用的单元测试。
主程序与 RVC 使用不同 Python 环境，先核实项目版本要求和可用解释器；不要把 RVC 依赖安装进主程序环境。

## 建立基线

1. 记录现有检查、已通过项、原有失败与无法验证项。新增检查工具前先确认仓库是否已有等效工具；若需要选型，选择最小集合并记录可重复运行的命令。
2. 将快速离线检查与设备集成测试分开。单元和契约测试不能默认启动 Ollama、下载模型、读取麦克风、播放声音、打开网页、运行文件清理或控制系统电源。
3. 按本次风险补覆盖：意图路由、上下文选择、错误传播、取消、任务结束、配置无效值与资源清理。不要用源码字符串匹配代替行为验证。
4. 静态检查分步引入。优先覆盖新增和修改的边界类型，不用全局忽略掩盖错误，也不为使检查通过一次格式化所有无关代码。
5. 配置校验在启动有副作用的组件之前完成，错误应指出配置项；保留兼容默认值，涉及持久格式变化时说明迁移。依赖锁定需考虑 Windows、Python 版本和 RVC 独立环境，不能把当前机器的全部包直接当作项目依赖。

## 与本项目相关的故障用例

按修改范围选择，不要求每次全部运行：
- Ollama 连接失败、响应格式异常、流中途断开、用户取消。
- TTS/RVC 失败、播放失败、队列积压、关闭期间仍有任务。
- 麦克风不可用或识别为空；纯文本路径仍能独立测试。
- 上下文预算、会话隔离、持久记录恢复；记忆删除同步影响衍生索引时也需验证。
- 系统意图通过 fake 或 dry-run 验证策略；遵守 `.cursor/rules/system-safety.mdc` 与 `src/core/safety.py`，不真实关机、重启、锁屏。

## 测量与日志

对实时链路记录说话结束、识别完成、模型首段、音频准备完成、播放开始等时间点，并使用适合测量持续时间的时钟。区分冷启动和预热后结果，说明样本量、模型、量化、上下文、RVC 状态及并发负载。
性能目标需结合基线确定，不凭硬件型号承诺延迟。日志优先记录轮次标识与阶段耗时，避免默认写入完整语音转写、对话、记忆和敏感配置。

## 完成标准

交付检查入口、必要的行为测试及简短验证结果。明确区分通过、失败、未运行与受环境限制；对未运行项给出复现条件。
相关检查通过后停止重复验证，除非新改动或失败需要进一步调查。质量工具通过不能替代真实语音体验验收。
