# 渐进式重构

## 项目约束

- 本项目已有可用版本。Windows 优先，未来可能接入 Quest 3；3D 格式与引擎未定。保留现有 CLI 入口及已确认行为，不提前引入 XR 框架。
- 开始前读取仓库根目录 AGENTS.md、README.md、相关调用方与测试。涉及系统能力时读取 `.cursor/rules/system-safety.mdc` 与 `src/core/safety.py`。规则文件若缺失，报告缺失并以已核实的安全实现为依据，不推定获得额外操作权限。
- 检查工作区变更；保留用户与 Cursor 的未提交工作。路径均相对仓库根目录，移动后应搜索新位置，不假定旧文件永久存在。

## 工作步骤

1. 画出本次修改涉及的调用链，并记录外部可观察行为：输入、输出、错误、配置、线程或子进程、副作用。只读审计时不要运行会启动设备、清理文件或触发系统控制的入口。
2. 选定一个可独立验证的职责边界。优先检查 `src/core/assistant.py` 的依赖装配、`src/llm/ollama_client.py` 的会话耦合，以及 `src/cli/voice_session.py` 的会话控制；这些是检查入口，不是预先确认的缺陷清单。
3. 对缺少覆盖且将改变的关键行为补充基线测试。使用假的模型、音频和系统适配器，避免测试依赖联网、GPU、麦克风或真实电脑操作。
4. 先在旧入口背后替换实现，保持调用方可运行；只有任务涉及多种实现或需要隔离副作用时才增加接口。不要为了目录整齐一次搬动所有模块。
5. 若发现原有行为存在缺陷，区分“保持行为的迁移”和“改变行为的修复”，在变更说明及测试中明确区分。不要为保持兼容复制危险行为。
6. 验证本次调用链、错误路径和退出路径，检查导入、配置和文档引用。新实现验证完成并确认无调用方后再删除旧路径。

## 不变量

- 保留 SafetyPolicy 执行边界；系统测试使用 fake 或 dry-run，不触发真实关机、重启、锁屏。
- 不将错误文本当作成功结果，不把取消当作普通失败重试；若当前实现如此，明确作为另一个行为修复处理。
- 不执行重置工作区、覆盖他人修改或删除模型/运行数据来完成重构。
- 避免在模块导入时新增模型加载、音频设备打开、线程启动等副作用。

## 交付与完成标准

说明迁移了哪一项职责、兼容入口、验证结果、已知限制和回退办法。回退按本次修改或独立提交实施，不回滚他人的工作。
重构完成应能用不依赖真实设备的测试证明关键行为保持；真实环境未测时明确列出，不声称功能已端到端验证。
