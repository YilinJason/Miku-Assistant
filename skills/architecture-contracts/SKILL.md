# 架构与契约

## 先确认现状

读取根目录 AGENTS.md；根据任务检查 `src/core/assistant.py`、`src/core/router.py`、`src/core/handlers/`、`src/llm/ollama_client.py`、`src/voice/` 和 `src/extensions/character_interface.py` 的相关部分。
以实际调用关系为准。角色占位接口不能被描述为已经接通 3D，现有返回字符串的调用不能被描述为端到端流式链路。

## 设计决策

1. 明确变化动机及当前约束，列出本次需要替换或独立测试的依赖。优先使用模块化单体与进程内接口；保留已有必要的 RVC Worker 隔离，不仅为未来 Quest 引入网络服务。
2. 将业务流程与依赖装配分离。对话核心通过窄接口使用模型、音频、存储和工具；Windows 操作与渲染实现留在适配器。复用现有模块，不强制一次性重排目录。
3. 为实际跨边界的数据定义类型与语义：必填/可选字段、单位、顺序、完成条件、失败、取消、超时和所有权。采用项目可支持的 dataclass、Protocol 或等效实现，不为简单数据强加框架。
4. 区分模型传输、会话记录、上下文构建和长期记忆。模型客户端不应决定记忆事实；持久层不得将模型推断自动标为用户确认事实。
5. 对跨进程或持久化契约定义版本与兼容策略；普通内部函数无需机械增加版本号。

## 对话和资源契约

- 增量生成应向调用方逐段提供内容，而非收集完整回复再返回。明确生成结束与播放结束是不同事件。
- 多轮并发或可打断链路携带 session_id 与 turn_id，接收方可拒绝过期结果。为取消规定传播范围、剩余音频处理和历史提交策略。
- 定义无语音、识别失败、服务不可用、用户取消等不同结果，避免统一为空字符串或普通回复。
- 每个线程、任务、音频流、连接和子进程均有明确持有者与关闭入口；说明部分初始化失败如何回收。不要把 daemon 线程退出当作资源清理完成。
- 有界队列明确满载时阻塞、拒绝或替换的策略；重试明确上限，具有外部副作用的动作不能盲目重试。
- UI 和角色使用业务状态或事件，不读取适配器私有字段。暂不指定 Quest 的部署方式和 3D 引擎。
- 工具操作经现有 SafetyPolicy；设计接口本身不意味着允许执行真实系统操作。

## 交付与验证

小改动给出接口说明与调用示例；影响多个子系统的决策写入 `docs/architecture/` 的简短决策记录，包含问题、选择、替代方案、取舍及迁移步骤。
用假适配器验证相关不变量，例如取消后不接收旧轮次内容、适配器故障不阻止资源关闭、失败不被记录为成功对话。只验证本次涉及的契约。
指出未来能力与当前实现之间的差距，不把接口声明当作功能完成。
